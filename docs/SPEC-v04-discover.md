# SPEC v0.4 — Discovery: «найти ещё такого» по выбранному архетипу

Ядро ценности продукта (инсайт основателя: «анализ — хорошо, но ценности мало; нужен
поиск похожего по категории, которую выберет человек»). Продуктизация экспериментального
discover.py: сиды из кластера → радио YT Music → анализ кандидатов → ранжирование.

Зависимости: v0.3 (архетипы, пермалинки, джобы) построено; Takeout-волна должна
завершиться ДО начала этой (общие файлы: jobs.py, routes, portrait page).

## A. Backend

### A1. videoId в портрете (пререквизит)

- `portrait.py`: в `points[]` добавить `"videoId": str|null` (есть и в demo-CSV, и в
  плейлист/Takeout-потоках). Контракт-аддитивно, фронт-опционально.
- Сохранённые ранее портреты без videoId в points: discovery для них отвечает 409
  «портрет старой версии — построй заново» (фронт покажет человеческое сообщение).

### A2. Джоба discovery

- `POST /api/discover` body `{portrait_id: str, cluster: int (индекс в clusters[]),
  limit: int<=25 default 15}` → 202 `{job_id}` (общая джоба-инфраструктура; stage'ы:
  `seeding` → `radio` → `analyzing` → done).
  404 незнакомый portrait_id; 422 кривой cluster; 409 портрет без videoId в points.
- `app/engine/discovery.py`:
  1. Сиды: точки выбранного кластера, ближайшие к центроиду (в стандартизованном
     MOOD_FEATURES-пространстве библиотеки портрета), у которых есть videoId — до 5 шт.
  2. Кандидаты: анонимный `YTMusic().get_watch_playlist(videoId=seed, limit=15)` по
     каждому сиду; исключить все videoId портрета и дубли; ≤2 трека на артиста;
     потолок кандидатов = limit*3 (лишние отбрасываются с конца).
  3. Каждый кандидат: существующий превью-каскад (кэш!) → analyze → признаки.
  4. `match` 0..100: стандартизованное расстояние d до центроида кластера по
     MOOD_FEATURES, где темп октаво-толерантен (брать min расстояния по {t, 2t, t/2} —
     урок «kah»); match = round(100 * exp(-d/2)). Порог отдачи: match >= 35.
  5. Результат в done-джобе: `{"discoveries": [{artist, title, videoId, match,
     tempo, key, mode, preview_url}], "cluster_label", "archetype", "listen_all_url"}`,
     отсортировано по match; listen_all_url = youtube.com/watch_videos?video_ids=
     топ-N videoId. preview_url — уже найденный превью-URL (для прослушивания на
     странице; НЕ проксировать через бэк, отдать как есть).
- Сохранение: discoveries дописываются в payload сохранённого портрета
  (`store.update_discoveries(portrait_id, cluster, discoveries)`) — чтобы /p/{id}
  показывал находки без пересчёта. Перезапуск discovery того же кластера перезаписывает.

### A3. Тесты (без сети)

- seeds: выбор ближайших к центроиду, пропуск точек без videoId, 409-ветка;
- кандидаты: monkeypatch get_watch_playlist — дедуп, ≤2/артист, исключение своих;
- match: октаво-толерантность (кандидат с t/2 темпом центроида не штрафуется),
  монотонность по расстоянию, границы 0..100;
- джоба: полный цикл с моками до done, контракт discoveries; 404/422/409.

## B. Frontend

- Карточка кластера (components/portrait-view.tsx): кнопка «⚡ Найти ещё такого»
  (только если у портрета есть portrait_id — т.е. он сохранён; для не сохранённого
  демо кнопка сохраняет молча и запускает).
- Секция результатов под карточками (или модально-встраиваемый блок):
  - прогресс: «Собираем радио по трекам-эталонам…» → «Слушаем кандидатов… N из M»;
  - список находок: match-бейдж (цвет кластера), artist — title, темп · тональность,
    кнопка ▶ (проигрывает preview_url через один общий <audio>; повторный клик — пауза;
    при переключении трека предыдущий останавливается), ссылка «открыть в YT Music»
    (music.youtube.com/watch?v=), сверху — «Слушать всё в YouTube Music» (listen_all_url);
  - мелкая подпись: «превью предоставлены iTunes/Deezer»;
  - состояния: пусто («радио не дало близких кандидатов — попробуй другой архетип»),
    ошибка, 409 → «этот портрет сохранён старой версией — построй заново».
- /p/{id}: если в payload есть discoveries — рендерить сразу (без пересчёта), кнопка
  «обновить подборку» запускает новую джобу.
- Types: опциональные поля, фронт не падает на старом бэке.

## C. Definition of Done

1. pytest зелёный (все старые + новые), без сети в тестах.
2. Живой e2e: сохранённый демо-портрет → POST discover (кластер «грустный бэнгер») →
   done → discoveries непустые, match убывает, preview_url играбельные (HEAD 200 хотя бы
   у первых 3), listen_all_url корректный.
3. npm build/dev по правилу «не строить при живом dev-сервере»; SSR-проверки страниц.
4. Прежние потоки не сломаны (demo/плейлист/Takeout, пермалинки, compare).
5. Консоль браузера чистая на портрете с discovery-секцией.
