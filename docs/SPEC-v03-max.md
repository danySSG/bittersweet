## A. Архетипы кластеров + хайлайты

### Архетипы

Кластеры получают человеческие имена из словаря продукта (это бренд-язык tastemap).
В `portrait.py`: `_archetype(cluster_means, lib_medians) -> {"name": str, "emoji": str}`
по правилам (проверять в этом порядке, первое совпавшее):

| условие (относительно медиан библиотеки) | name | emoji |
|---|---|---|
| bittersweet_mean >= 0.80 | «биттерсвит» | 🍬 |
| minor >= 0.6 И tempo > медианы И (percussive ИЛИ onset_rate > медианы) | «грустный бэнгер» | 🌒 |
| minor >= 0.6 И percussive < медианы И energy_rms < медианы | «тихая грусть» | 🌫️ |
| minor <= 0.42 И brightness > медианы | «светлая сторона» | ☀️ |
| percussive > медианы И onset_rate > медианы | «грув» | 🕺 |
| brightness < медианы | «тёмная материя» | 🌑 |
| иначе | «между строк» | 🌗 |

Дубликаты имён архетипов между кластерами допустимы ТОЛЬКО с суффиксом различия
(существующая дедупликация меток обязана работать и для архетипов: второй «грустный
бэнгер» → «грустный бэнгер · ~162 bpm»).

Контракт кластера: + `"archetype": {"name": "...", "emoji": "..."}`. Техническое имя
(«среднее · меланхоличное · тёмное») остаётся в `label` — фронт покажет его подписью.

### Хайлайты («самые-самые» треки)

Контракт портрета: + `"highlights": [{kind, title, track, value}]` — до 5 штук:
- `fastest` «самый быстрый» (max tempo, value «172 bpm»),
- `darkest` «самый тёмный» (min brightness, value «612 Гц»),
- `most_bittersweet` «самый биттерсвит» (max bittersweet, только если >= 0.8),
- `most_energetic` «самый заряженный» (max energy_rms),
- `most_yours` «самый типичный» (ближайший к центроиду всей библиотеки).
Трек может попасть только в ОДИН хайлайт (приоритет сверху вниз); < 10 треков — выдавать
сколько получится.

### Биттерсвит-перцентиль

`"bittersweet"` в контракте получает + `"percentile": int|null` — доля сохранённых
портретов (см. B), у которых bittersweet.share НИЖЕ текущего. null, если сохранённых
портретов < 5 (фронт тогда не показывает). Считается по таблице portraits на лету.

## B. Постоянные ссылки (портрет живёт после рестарта)

- SQLite (та же база cache.db): `portraits(id TEXT PK, created_at, source_label TEXT, payload TEXT)`.
  id — 8 симв. base32 (uuid4). payload — полный JSON портрета.
- По завершении джобы (status=done) портрет автоматически сохраняется; в состоянии джобы
  появляется `"portrait_id"`. source_label: «плейлист YouTube Music» / «демо» / далее «Takeout».
- `GET /api/p/{id}` → сохранённый портрет (+ поля id, source_label, created_at); 404 если нет.
- `POST /api/demo/portrait/save` → сохраняет демо-портрет, возвращает {portrait_id}
  (для шаринга демо).
- Лимит хранения не вводим (MVP), но id неугадываемые.

## C. Сравнение вкусов — «совместимость по звуку»

- `GET /api/compare?a={id}&b={id}` (id из B):
  - `score` 0..100 — косинусная близость стандартизованных векторов-отпечатков
    [tempo_median, minor_share, brightness_mean, bittersweet.share, доли архетипов],
    отмасштабированная в 0..100 (клип отрицательных в 0);
  - `common_archetypes`: имена архетипов, есть у обоих;
  - `facets`: [{name: «темп», a: 118, b: 96, unit: "bpm"}, {минор, %}, {яркость, Гц},
    {биттерсвит, %}] — для столбиков-сравнений;
  - `verdict`: строка по диапазону score: >=80 «музыкальные близнецы», >=60 «звучите в унисон»,
    >=40 «есть общие волны», иначе «противоположности» (+ 1 предложение, чем именно похожи/различны —
    по максимально близкой/далёкой грани);
  - 404 на несуществующие id, 422 если a == b.

## D. Frontend

1. **Страница портрета** (`/portrait` — все потоки, и новая `/p/[id]`):
   - карточка кластера: сверху крупно `emoji + archetype.name`, техническое label — мелкой
     подписью; остальное как было;
   - блок «Самые-самые» после кластеров: чипы хайлайтов (kind-иконка, title, track, value);
   - биттерсвит-блок: если есть percentile — строка «биттерсвитнее, чем у N% портретов»;
   - «Поделиться»: если есть portrait_id — копирует ПОСТОЯННУЮ ссылку `{origin}/p/{id}`
     (для демо — сначала POST save). Тултип «ссылка скопирована»;
   - кнопка «Скачать карточку» (share-card, см. 3);
   - `/p/[id]`: рендер сохранённого портрета (GET /api/p/{id}); шапка «портрет · {source_label}
     · {дата}»; те же share-кнопки; CTA «Построить свой» → лендинг.
2. **Сравнение** (`/compare`):
   - форма: два поля «ссылка или ID портрета» (принимать и /p/{id}-URL, и голый id) → GET compare;
   - результат: большой score с вердиктом, общие архетипы (эмодзи-чипы), facets — пары
     горизонтальных столбиков a/b с подписями;
   - на странице портрета после копирования ссылки — подсказка «Отправь другу и сравните вкус →
     /compare».
3. **Share-card** (из SPEC-v02b, уточнение): PNG 1080×1920 канвасом на клиенте; вверху
   крупно эмодзи+имя ТОП-архетипа, мини-скаттер, топ-3 архетипа с долями, биттерсвит-%,
   водяной знак tastemap + /p/{id} (если есть). Кнопка со спиннером на время рендера.
4. **Лимиты**: default limit 25→40 (lib/api.ts), поллинг-таймаут 5→8 мин.
5. **Лендинг**: hero-полировка — лёгкая CSS-анимация «живых точек» (10-15 разноцветных
   точек-кластеров, медленный дрейф transform'ами, prefers-reduced-motion: отключить);
   вторая строка тэглайна: «Архетипы вкуса, карта настроений и совместимость — по реальному
   звуку, а не тегам». Секция «как это работает» из 3 шагов (ссылка → анализ звука → портрет).

## Definition of Done

1. `uv run pytest` зелёный (новые тесты: архетипы — таблица правил покрыта таблично;
   дедуп архетипов; highlights непересекающиеся; save/load портрета; compare score
   симметричен, a==a → 100, 404/422-ветки). Без сети.
2. `npm run build` зелёный.
3. Живой цикл: demo-портрет → save → GET /api/p/{id} → фронт /p/{id} рендерит; compare
   двух сохранённых → валидный JSON и страница.
4. Share-card: PNG скачивается, > 50 KB, 1080×1920.
5. Плейлист-поток и демо не сломаны; страница /portrait рендерит архетипы и хайлайты.
6. Консоль браузера без ошибок на /, /portrait?demo=1, /p/{id}, /compare.
