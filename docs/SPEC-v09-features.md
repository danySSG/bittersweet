# SPEC v0.9 — «Фишки»: радио архетипа, discovery-по-точке, мои портреты, галактика-hero

Мандат основателя: «давай добавлять больше фишек». Курация по его принципам:
слушаемость, интерактивность, wow-виз в продукте, явный контроль.

## A. Радио архетипа (frontend)

- `lib/use-audio.ts` расширить режимом очереди: `playQueue(tracks: {url, label, meta}[], startIndex)`,
  автопереход по `ended`, next/prev/pause, текущий индекс наружу.
- В discover-section: кнопка «📻 Радио» рядом с «Слушать всё» — играет находки С preview_url
  подряд (пропуская без превью). Кнопки ▶ на строках работают как прежде (и синхронизированы
  с очередью: клик по строке = прыжок очереди на неё).
- Мини-плеер: фиксированная полоса внизу вьюпорта, появляется только при активной очереди:
  эмодзи архетипа + «artist — title» + кнопки prev/pause/next + тонкий прогресс 30-сек превью
  + крестик (стоп и скрыть). Не перекрывает контент (padding-bottom при активном плеере).
  prefers-reduced-motion не относится; мобильная ширина — уважать (сжимать label).

## B. Discovery по точке карты (backend + frontend)

### Backend

- `POST /api/discover` принимает АЛЬТЕРНАТИВНО к {portrait_id, cluster}:
  `{portrait_id, point: {x: float 0..100, y: float 0..100}}` — координаты в осях карты
  (x = valence-перцентиль, y = energy-перцентиль, как в points[]).
  Валидация: ровно один из cluster/point; иначе 422.
- Логика point-режима в engine/discovery.py:
  1. из points[] портрета взять k=7 ближайших к (x,y) точек (евклид по x/y), у которых
     есть videoId и features; если <3 таких — 409 с человеческим сообщением;
  2. сиды = до 5 из них; target-вектор = среднее их MOOD_FEATURES (стандартизация по
     библиотеке портрета — как в cluster-режиме);
  3. дальше конвейер БЕЗ ИЗМЕНЕНИЙ (радио-кандидаты, октаво-толерантный match к target).
- В done-результате: `target: {kind: "point", x, y, label: "точка карты: настроение N · энергия M",
  near: [до 3 label ближайших твоих треков]}` (для cluster-режима target.kind="cluster",
  прежние поля не менять — аддитивно).
- Персистентность в payload портрета: discoveries по точкам хранить под ключом
  `point:{round(x)}:{round(y)}` (перезапись при повторе той же округлённой точки).

### Frontend

- 2D-карта: клик по пустому месту карты → маркер-прицел 🎯 в точке + поповер:
  «Найти музыку здесь» (+ мини-подпись «настроение N · энергия M») и «Отмена».
  Запуск → та же секция «Ещё такого» с заголовком «🎯 точка карты» и подписью near-треков.
- Галактика: клик по звезде (уже есть hit-test ближайшей) → тот же поповер с x/y этой
  звезды. Клик мимо звёзд — ничего (в 3D пустота неоднозначна).
- Пока идёт point-discovery, маркер пульсирует; по done — маркер остаётся с бейджем
  числа находок.

## C. «Мои портреты» + эволюция вкуса (backend + frontend)

### Backend

- `GET /api/portraits?limit=50` → список новейших: [{id, source_label, created_at,
  n_tracks, top_archetype: {name, emoji}, fingerprint, bittersweet_share}].
  MVP-локально возвращает все (продукт однопользовательский до деплоя);
  КОММЕНТ в коде: перед публичным деплоем скоупить по owner — privacy.
  Лёгкий парс payload без полной десериализации points (не тащить тяжёлое).

### Frontend

- Страница `/portraits`: сетка карточек (эмодзи топ-архетипа крупно, source_label, дата,
  N треков, биттерсвит-%) → ссылки на /p/{id}. Ссылка «Мои портреты» в шапке лендинга
  и страницы портрета.
- Если ≥2 портретов: блок «Эволюция вкуса» сверху — SVG-график без библиотек:
  линии tempo_median, minor_share, bittersweet_share по created_at (нормировать в 0..100,
  легенда с цветами, tabular-nums подписи); + дельта-чипы «за период: минор +N пп,
  биттерсвит −M пп, темп +K bpm» (первый vs последний портрет).
- Пустое состояние: «построй первый портрет» → лендинг.

## D. Галактика-hero на лендинге (frontend)

- На лендинге за hero-текстом — приглушённая живая галактика: клиентский фетч
  /api/demo/portrait, GalaxyView в фоновом слое (opacity ~0.5, pointer-events: none,
  автовращение медленнее обычного). Бэк недоступен → тихий фолбэк на текущие CSS-точки.
  prefers-reduced-motion → статичный кадр без вращения. Существующие CSS-точки убрать
  при активной галактике (не дублировать).

## Definition of Done

1. pytest зелёный; новые тесты: point-валидация (оба/ни одного → 422), сиды по точке
   (ближайшие, пропуск без videoId, 409 при <3), target в результате, ключ point:x:y
   в payload, GET /api/portraits (поля, сортировка, лёгкость — не разворачивает points).
2. Мокированный point-discovery цикл до done; живой smoke: GET /api/portraits на живой
   базе (там 21 портрет) → валидный список с top_archetype.
3. Фронт: сборка по правилу (NEXT_BUILD_DIR=.next-build!); SSR: /portraits → 200,
   лендинг содержит canvas галактики; grep: мини-плеер, поповер точки.
4. Прежние потоки не сломаны: вся сюита + /portrait?demo=1 и cluster-discovery живы.
