## A. Импорт Google Takeout (YouTube Music) — источник №2

Пользователь загружает свою выгрузку Takeout → портрет всей библиотеки. Юридически чистый
путь (пользователь сам выгружает собственные данные — модель stats.fm).

### Факты о формате (исследование 2026-07-10, проверено по реальным выгрузкам на GitHub + живым запросам)

1. Структура: `Takeout/YouTube and YouTube Music/` (имя папки ЛОКАЛИЗУЕТСЯ: нем.
   «YouTube und YouTube Music», итал. «YouTube e YouTube Music»; русскую строку считать
   неизвестной — искать папку по содержимому, не по имени).
2. `music-library-songs/music-library-songs.csv` — ЕДИНСТВЕННЫЙ файл с готовыми метаданными:
   заголовок `Song URL,Song Title,Album Title,Artist Names` (регистр слов плавает между
   выгрузками — если матчить, то case-insensitive; лучше позиционно). videoId извлекается
   из Song URL (`music.youtube.com/watch?v=<id>`).
3. `playlists/playlists.csv` — индекс плейлистов (имя в колонке `Playlist Title (Original)`).
   Пер-плейлистные файлы: `playlists/<Имя>-videos.csv` ИЛИ `<Имя>.csv` (оба варианта в природе);
   содержимое — ДВЕ колонки: `Video ID,Playlist Video Creation Timestamp`. Названий треков НЕТ.
4. Лайки YT Music («Liked Music») — обычный плейлист с ЛОКАЛИЗОВАННЫМ именем файла
   (итал. «Mi piace.csv»; русское имя неизвестно) → кандидатов в «лайки» определять
   эвристикой не по имени, а предлагать пользователю выбор, какой плейлист анализировать,
   если их несколько (MVP: брать объединение всех + music-library-songs, свежие первыми).
5. ЗАГОЛОВКИ CSV локализуются (подтверждено zh-TW: `影片 ID,播放清單影片的建立時間戳記`) →
   парсинг ПОЗИЦИОННЫЙ: пропустить первую строку; колонка 0 валидна, если это 11-символьный
   YouTube ID (regex `^[A-Za-z0-9_-]{11}$`) или URL с v=; колонка с ISO-8601 — timestamp.
6. oEmbed: `https://www.youtube.com/oembed?url=...&format=json` жив (живой тест 2026-07-10),
   отдаёт `title` + `author_name`; для авто-треков `author_name = "<Artist> - Topic"`
   (суффикс « - Topic» отрезать, title = чистое название). Отказы: 401 (embed запрещён),
   403 (эпизодически), 404 (удалено). Лимиты не документированы → троттлинг ≤4 req/s,
   экспоненциальный бэкофф на 403/429, fallback: noembed.com (жив, тот же формат).
7. История (`history/watch-history.json`) в MVP НЕ парсим (отдельная сущность, v-next).

### Backend

- `POST /api/analyze/takeout` — multipart upload: принимает `.zip` (вся выгрузка) ИЛИ
  одиночный `.csv`; максимальный размер 100 МБ (413 при превышении); из zip читаем ТОЛЬКО
  нужные csv (zipfile, без распаковки на диск целиком; защита от zip-bomb: суммарный
  размер распакованных нужных файлов ≤ 50 МБ).
- `app/sources/takeout.py`:
  - `parse_takeout(file) -> list[RawEntry]` — ищет музыкальные CSV по именам/структуре
    (EN и RU локали!), парсит; RawEntry = {video_id?, artist?, title?, source_file};
  - выбор при нескольких кандидатах: приоритет «песни библиотеки» > «понравившиеся» > плейлисты;
  - устойчивость: BOM, ';' vs ',', пустые строки, заголовки по-русски; определение колонок
    по нескольким эвристикам (имена EN/RU + позиция).
- Резолвинг video_id → artist/title, когда в CSV нет названий:
  - `app/engine/resolver.py`: YouTube oEmbed (без ключа), троттлинг ≤4 req/s, ретраи;
    парс `author_name`: суффикс « - Topic» отрезать (это артист авто-канала);
    кэш в SQLite: таблица `video_meta(video_id PK, artist, title, resolved_at)`;
  - если oEmbed недоступен/404 (удалённое видео) — трек пропускается, считается в unmatched.
- Дальше — СУЩЕСТВУЮЩИЙ конвейер: та же джоба (jobs.py), тот же прогресс, тот же портрет.
  `run_takeout_job(job_id, entries, limit)`: берёт ПОСЛЕДНИЕ по времени добавления limit
  треков (свежие лайки интереснее старых), default 40, max 60.
- В progress добавить поле `stage: "parsing" | "resolving" | "analyzing"` (фронт показывает этап).

### Frontend

  умеет поллить; добавить поддержку ?job= без ?playlist=).
- Подсказка-раскрывашка «Как получить выгрузку»: takeout.google.com → снять всё, выбрать

  «музыкальная библиотека» и «плейлисты» → создать экспорт → скачать zip (обычно минуты).
- Прогресс-этапы: «Разбираем файл…» / «Определяем треки… N из M» / «Анализируем… N из M».

## B. Share-card — вирусный хук

Кнопка «Скачать карточку» на странице портрета: генерирует PNG 1080×1920 (сторис-формат)
клиентским canvas — БЕЗ сервера.

- `lib/sharecard.ts`: `renderShareCard(portrait, sourceLabel) -> Promise<Blob>`:
  - фон: тёмный (#0b0b10) с мягким градиентом в цвета топ-2 кластеров;
  - контент: «акустический портрет» (моно, ВЕРХНИЙ регистр, letter-spacing), мини-скаттер
    (точки по x/y из portrait.points, цвета кластеров), топ-3 кластера строками
    «label · N% » с цветными маркерами, блок биттерсвит «N% — грустные, но энергичные»,
    внизу — «tastemap» (водяной знак) и sourceLabel («плейлист YouTube Music» и т.п.);
  - шрифты системные (canvas: -apple-system / monospace), НЕ грузить внешние;
  - devicePixelRatio-безопасно: канвас фиксированно 1080×1920.
- Кнопка рядом с «Поделиться»: «Скачать карточку» → a[download="tastemap-portrait.png"].
  Состояние загрузки на время рендера. Ошибок сети быть не может (всё локально).
- Существующую кнопку «Поделиться» (copy-link) не трогать.

## C. Лимиты плейлиста

- Frontend `lib/api.ts`: default limit 25 → 40 (потолок бэка).
- Frontend поллинг-таймаут: 5 мин → 8 мин (40 треков в худшем случае ~5-6 мин).
- Backend: без изменений (le=40 уже стоит); в `routes/analyze.py` замечание-коммент,
  почему 40 (iTunes ~20 req/min — см. previews.py).

## Definition of Done

1. `uv run pytest` — все старые + новые зелёные, без сети.
2. `npm run build` — зелёный.
3. Живой smoke Takeout: собрать синтетический zip в структуре реального Takeout
   (RU-локаль), загрузить через API с реальной сетью (oEmbed + превью на 10-12 реальных
   video ID популярных треков) → job done → валидный портрет.
4. Share-card: в браузере на /portrait?demo=1 нажать «Скачать карточку» — получить PNG
   1080×1920, файл открывается, содержит заголовок/кластеры (проверка скриншотом канваса
   или размером файла > 50KB).
5. v0.1/v0.2 не сломаны: demo-портрет и плейлист-поток работают.
