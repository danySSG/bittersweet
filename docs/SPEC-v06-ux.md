# SPEC v0.6 — UX-волна по фидбеку основателя после первого реального входа

Фидбек (2026-07-10, после первого OAuth-входа): (1) лимит анализа не должен быть скрытым
потолком; (2) анализ НЕ должен стартовать сам после входа — нужна явная кнопка;
(3) 3D-вид — в продукт; (4) «самые-самые» и примеры кластеров должны проигрываться.

## A. Backend

### A1. Глубина анализа и сводка

- `GET /api/youtube/summary` (требует сессию): `{channel_title, likes_total}` —
  likes_total из pageInfo.totalResults первого playlistItems.list (1 unit). 401 без сессии.
- `POST /api/analyze/youtube`: limit до **200** (le=200, default 40). Забор лайков —
  паджинация до max(limit, 200) свежих. Прогресс уже есть.
- То же для плейлиста/Takeout: le=40 → le=200 (default оставить 40); в комменте — почему
  200 разумный потолок MVP (синхронная джоба ~15-20 мин в худшем случае).

### A2. Превью для прослушивания всего проанализированного

- Таблица features: ALTER TABLE ADD COLUMN preview_url TEXT (НЕ пересоздавать — в кэше
  ценные дескрипторы; sqlite ALTER ADD поддерживает; обработать «column already exists»).
- pipeline: при успешном матче сохранять preview_url в кэш вместе с признаками;
  кэш-хит возвращает и preview_url.
- `POST /api/preview/resolve` body `{items: [{artist, title}], max 24}` → `{urls: [str|null]}`:
  для каждого — сначала preview_url из кэша, иначе живой каскад (и дозапись в кэш).
  Существующий троттлинг обязателен. Это для старых кэш-записей без preview_url.
- В контракте портрета: `highlights[].preview_url` и `clusters[].examples` СТАНОВЯТСЯ
  объектами `{label, preview_url|null}` — ОСТОРОЖНО: это ломает фронт-типы; сделать
  аддитивно: examples остаются строками, добавить параллельное поле
  `examples_rich: [{label, preview_url}]`; highlights получают preview_url (может null).
  Для свежих портретов заполняется из кэша при построении; для демо — тоже (кэш).

## B. Frontend

### B1. Экран «перед стартом» (убрать автостарт)

- `/portrait?source=youtube`: connected → карточка: «YouTube: {channel_title} ·
  {likes_total} лайков» + выбор глубины (радио-чипы):
  «Быстрый — 40 треков · ~2-3 мин» / «Глубокий — 120 · ~7-10 мин» /
  «Максимум — 200 · ~15-20 мин» + кнопка «Построить портрет» → POST + существующий
  прогресс. НИКАКОГО автостарта.
- Один нюанс: после done показать подпись «проанализировано N из {likes_total} лайков —
  глубину можно увеличить» с кнопкой пере-анализа.

### B2. 3D-галактика

- `components/galaxy-view.tsx`: canvas-движок (перенести из прототипа — вращение
  «схватил объект» (знаки уже выверены: rotY -= dx, rotX -= dy), автовращение с паузой
  при drag, тултипы по ближней точке, DPR≤2, prefers-reduced-motion → без автовращения).
- Оси из points[].features (клиентские перцентили): X = 1-minor_score, Y = композит
  (tempo, energy_rms, percussive, onset_rate), Z = brightness. Цвет — кластер.
- На карте портрета — переключатель «Карта | Галактика» (сегмент-контрол над сценой,
  состояние в useState; при отсутствии features у точек (старые портреты) — переключатель
  скрыт).
- Подпись осей в 3D: «X настроение · Y энергия · Z тембр (глубина)».

### B3. Слушать всё

- Хук useAudioPlayer уже есть (discovery) — вынести в lib/use-audio.ts, переиспользовать
  в трёх местах: discovery (как было), хайлайты (▶ на чипе при наличии preview_url),
  примеры кластеров (examples_rich).
- Для строк без preview_url: по клику — ленивый POST /api/preview/resolve на видимые
  элементы (батч), кнопки появляются по мере разрешения; если null — кнопки нет
  (не дизейблить весь ряд).
- Атрибуция «превью: iTunes/Deezer» — один раз в футере портрета.

## C. Definition of Done

1. pytest зелёный; новые тесты: summary (401/200), limit=200 валиден/201 нет, ALTER
   идемпотентен, preview_url в кэше через pipeline, /api/preview/resolve (кэш-хит без
   сети в тесте, живой каскад замокан), examples_rich + highlights.preview_url в контракте.
2. npm build по правилу dev-сервера; tsc чистый.
3. Живой цикл: /api/demo/portrait содержит examples_rich и highlights с preview_url
   (кэш уже наполнен прошлыми прогонами — хотя бы часть не-null); resolve добирает
   не-null для пары известных треков (Burial Archangel).
4. Браузерные SSR-проверки; 3D-переключатель присутствует на /portrait?demo=1.
5. Прежние потоки не сломаны (вся сюита).
