и спросил, почему «треки скачут» (306 vs 437 — треки без превью молча выпадают).

## A. Перцептивный темп

### A1. features.py (новые анализы)

- После beat_track: кандидаты C = {t, t/2, t/4, 2t} ∩ [55, 180].
  Для каждого кандидата — сила пика автокорреляции огибающей атак на его лаге
  (окрестность ±2 бина, линейная интерполяция не нужна). Выбираем кандидата
  с максимальной силой; при пустом C — фолд t вдвое до попадания в [55, 180].
  Демо-эталон: превью «Ludovico Einaudi — Nobody Knows» даёт ~57-59 вместо 235
  (проверено вручную 17.07 — сильнейший пик диапазона на 59).
- Сырой t сохранять рядом: возвращать также tempo_raw (в кэш НЕ добавлять колонку —
  просто поле результата; в кэш пишется скорректированный tempo).
- Тесты: синтетический клик-трек 60 bpm с 16-ми (онсеты 4/сек) → beat_track может
  дать 240, наш выбор → 60; честный 120 bpm бит остаётся 120; edge: t=50 → фолд вверх.

### A2. Страховка для СТАРОГО кэша (portrait build-time)

- В build_portrait перед всеми расчётами: fold_cached_tempo(tempo, onset_rate):
  пока tempo >= 165 И onset_rate < tempo/60 * 0.55 (событий заметно меньше, чем
  «нот на долю») — tempo /= 2. Докстринг с обоснованием; примеры в тестах:
  (235, 2.1) → 117.5 → (117.5 < 165 стоп) 117.5; (162, 5.0) НЕ трогается (реальный
  дарквейв); (172, 9.8) не трогается.
- Применяется к df на входе: хайлайт «самый быстрый», медианы, архетипы, история —
  всё автоматически честнее при следующей перестройке/пересборке payload-производных.
- ВАЖНО: сохранённые payload'ы НЕ мигрировать массово; но observatory/story у портрета
  пересобираются при перестройке — не трогаем существующие.

## B. Честное покрытие

- Джобы youtube/takeout/playlist кладут в done-результат и в payload портрета:
  `coverage: {candidates: int, analyzed: int}` (candidates = найденных музыкальных /
  распознанных строк файла / треков плейлиста ДО матчинга превью).
- UI: в шапке портрета после «N треков» — приписка «· проанализировано N из M»
  (только если M > N; тултип: «для остальных не нашлось 30-сек превью в открытых
  каталогах — чаще всего это редкие или региональные треки»).
- История: в главе identity одно предложение при покрытии <85%: «Поймать удалось
  N из M твоих треков — самые редкие спрятались от каталогов превью; портрет честен,
  но чуть смещён к известному». STORY_VERSION -> 3.
- Тесты: coverage в done и payload всех трёх источников; фраза появляется/не
  появляется по порогу.

## C. Definition of Done

1. pytest зелёный: A1 (клик-тесты), A2 (таблица случаев), B; без сети.
2. Живой мини-smoke: анализ превью Эйнауди через новый features.analyze → tempo в
   [55, 70]; build_portrait на синтетике с (235, 2.1) больше не выдаёт «самого
   быстрого» с темпом > 180.
3. Фронт: приписка покрытия (защищена опциональностью), tsc, NEXT_BUILD_DIR-сборка,
   живые серверы не трогать.
4. Прежнее не сломано: вся сюита.
